Pages dropped out of Google after a deploy: a checklist

If organic traffic fell a few days after a release, check these five things first. Each one tells Google to drop or ignore pages, and each is easy to ship by accident.

  1. robots.txt. Open /robots.txt. A staging file with User-agent: * and Disallow: / blocks crawling of the whole site. Also check it returns 200: Google treats a robots.txt that returns 5xx as "disallow everything".
  2. meta robots. View the source of a key page and search for noindex in <meta name="robots"> or <meta name="googlebot">. CMS settings like WordPress's "Discourage search engines from indexing this site" add it to every page.
  3. X-Robots-Tag header. Run curl -sI https://example.com/ | grep -i x-robots. Server or CDN rules copied from staging often add X-Robots-Tag: noindex.
  4. Canonical. Check that <link rel="canonical"> points to the production URL, not staging., localhost or another environment.
  5. Status codes and redirects. Key pages should answer 200 directly or after one redirect, not 404, 5xx or a redirect loop.

The free checker runs all five against a list of URLs or your sitemap in one command:

node indexability-check.mjs --sitemap https://example.com/sitemap.xml --max 200

After fixing it

Use URL Inspection in Search Console to request indexing of the most important pages, and resubmit the sitemap. Recovery usually takes days to weeks. To catch it next time before traffic drops, run the check after every deploy (it exits with code 1 on any problem, so it can fail a CI pipeline).
